# DSH Launcher v0.1.4 发布说明

发布日期：2026-09-21
GitHub Release：https://github.com/Yinxe/dsh-luncher/releases/tag/v0.1.4

> 本文件由 `npm run notes:archive` 从 CHANGELOG.md 生成，请勿手改。

### 修复

- **插件「检查更新」不再串 profile**：检查更新还在跑的时候切换 profile，此前旧 profile 的结果晚到会盖到新 profile 的列表上，「升级」按钮可能拿着旧 profile 的规格把包装错地方；现在切换后旧结果直接丢弃。
- **内置终端切 profile 自动收回隔离视图**：展开「查看其他 profile 的任务」后切到一个没有跨 profile 任务的 profile，此前开关按钮会消失、视图卡在混合模式回不去；现在切换 profile 会自动收起。
- **Windows / macOS 启动不再白屏「未响应」**：启动时创建托盘菜单会在 **UI 线程**上枚举系统进程（Windows 上要起 PowerShell，还要为每个 PID 起 `tasklist.exe`），窗口能出现但界面一直空白、标题栏显示「未响应」，把那些 `tasklist` 结束掉才恢复；现在启动路径不做任何进程枚举，托盘先显示「正在检测实例…」，真实状态由后台线程在几百毫秒内补上。
- **不再为每个监听端口各起一个 `tasklist.exe`**：Windows 上非本用户进程（`svchost` 等系统服务）的命令行读不到，此前这些进程被整条丢弃，于是「端口占用者不在进程表里」→ 每个监听端口都回退一次逐 PID 探测，一轮十几个 `tasklist` 叠加、还会闪一屏黑色控制台窗口；现在拿不到命令行的进程也保留在进程表里，逐 PID 起子进程的探测整体移除。
- **进程枚举只由一个后台线程执行，且带超时**：「前端 3 秒轮询 + 托盘 3 秒轮询」此前会各起一轮枚举，一轮没跑完下一轮就叠上来（`tasklist` 数量 16 → 18 → 20 持续增长、不回收）；现在任何时刻只有一个枚举在跑，子进程卡死会被超时结束，而不是永久占住线程。
- **进程表读不到时不再误删独立实例**：枚举失败（PowerShell 被禁用、超时）此前被当成「进程不存在」，会清掉独立进程登记条目，界面从此再也看不到、也停不掉那个实例；现在无法判定时保守保留。
- **保存设置 / 安装 / 卸载 / 改名 / 删除 profile / 读实例日志不再卡界面**：这些操作里的实例检查同样要枚举系统进程（Windows 上 1s 级），此前跑在主线程上会让窗口短暂无响应，现在都放到后台线程执行。

### 新增

- **启动耗时与崩溃留痕**：新增 `~/.dsh-launcher/logs/`——`startup.log` 记录启动各阶段与进程枚举的耗时，`panic.log` 记录崩溃位置与消息（release 版是 Windows GUI 程序，panic 默认没有任何输出）。白屏、崩溃这类问题下次可以直接看这两个文件定位。
