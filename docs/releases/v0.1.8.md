# DSH Launcher v0.1.8 发布说明

发布日期：2026-09-21
GitHub Release：https://github.com/Yinxe/dsh-luncher/releases/tag/v0.1.8

> 本文件由 `npm run notes:archive` 从 CHANGELOG.md 生成，请勿手改。

### 修复

- **插件开关在全新 profile 上不再一按就报 YAML 错**：profile 模板自带的 `cordis.patch.yml` 是「一串注释 + 一行 `[]`」，而 `[]` 是 flow 写法 —— 启动器往后追加 `- id: …` 条目时，同一个文件里就出现了**两个 YAML 文档**，写前校验直接失败，报「YAML 语法错误：deserializing from YAML containing more than one document is not supported」，于是**任何插件的启用/停用都点不动**（快捷配置那条写入路径早有处理，插件启停这条漏了）。现在追加前先摘掉这行空占位（`[ ]` 这种带空格的写法同样认，插件启停与快捷配置共用同一套判定），条目被清空后再把 `[]` 放回去，文件始终保持「单文档 + 顶层数组」的形态；万一文件已经被手写坏成多文档，报错也会直接说明「删掉那行 `[]`」，不再只丢一段解析器原文。
- **插件「更新」不再永远失败（中断克隆留下的坏 HEAD）**：`git clone` 中途被打断（断网、超时被杀）会在本地克隆里留下一个坏掉的 HEAD —— `ref: refs/heads/.invalid`。这个名字不合法，git 便一边「查不到这个分支」、一边「拒绝覆盖它」，于是之后每一次更新都只报 `cannot lock ref 'HEAD': reference already exists`，点多少次都不会好，插件也再更新不了（Linux/Windows 实测都中）。现在安装与更新在 fetch/pull 之前会先检查这个哨兵 HEAD，发现就把它修回真实分支、并按 `origin` 把本地分支补出来，任务日志里写明修了什么；只有这一个形态会被动，正常仓库（包括分离 HEAD）一律不碰。
- **带代理前缀的 git 地址不再把仓库永久弄脏**：代理前缀（如 `gh.dpik.top`）是临时的，而 `origin` 是永久的 —— 一旦 `<前缀>https://github.com/...` 被写进远端配置，代理失效或换域名后这个克隆就**永久 `pull` 不动**，而且启动器的加速注入只认 `https://github.com/`，对脏地址完全不生效（手抄过一次带前缀的 clone 地址就会中招）。现在：clone 前自动把前缀剥掉（落点目录名也按原始地址算），**已存在的克隆在 fetch/pull 前会把 `origin` 修回原始地址**并在任务日志里写明改了什么；安装页遇到带前缀的地址会提示「会按原始地址克隆」。顺带说明：启动器自己 clone 出来的仓库**从来不写前缀** —— 加速是进程内的 git 配置注入（`url.<前缀>.insteadOf`），进程结束即失效，`origin` 始终是 `https://github.com/...`，所以代理挂了只会退回直连，不会把克隆卡死。
- **版本表的「更多操作」菜单点得开了**：上次改动把它做成「宽屏铺开次要操作 / 窄屏收进 ⋯ 菜单」，结果两处**同时**失灵 —— 一是宽窄屏切换的 Tailwind 类名是拼接出来的（`${WIDE}:hidden`），Tailwind 只扫源码里的完整类名、对应 CSS 压根没生成，于是「铺开的次要操作」在任何宽度下都被隐藏，只剩一个 ⋯ 按钮；二是那个 ⋯ 按钮点不开：Radix 的 `asChild` 触发器靠 Slot 给子元素挂 ref 才能拿到真实 DOM，而 shadcn 的 Button 是普通函数组件、不转发 ref（上游按 React 19 写，本项目是 React 18），控制台里报 `Function components cannot be given refs`，点下去毫无反应 —— 两者叠加等于版本表里「更新日志 / 打开安装目录 / 重装 / 卸载」这一个都点不到。现在：Button 改为 `forwardRef` —— 这也是所有 `asChild` + Button 触发器的共同根因（顶栏「更多操作与环境信息」那个 ⋯ 菜单、各处 `DialogClose` / `SheetClose` 里的关闭按钮都丢 ref、控制台都报同一句警告），宽窄屏类名改成字面量。实测容器 876px 时铺开 4 个次要操作、676px 与 396px 时只剩 ⋯ 按钮，两处都能正常弹出菜单。

### 新增

- **在线下载页（DeepSeek Harness 启动器）：不用再翻 Release 页面找包** —— <https://yinxe.github.io/dsh-luncher/>。按 Windows / macOS / Linux 分行列出每个安装包（.exe / .msi / .dmg / AppImage / .deb / .rpm），每行都带**可复制的直链**与体积，并自动标出你当前系统的那个包。页面上可切换**自建源（R2）**与 **GitHub Release** 两条通道，切换后全页直链、说明与安装命令一起换（选择会记住，也支持 `?source=github` 深链）：前者是路径永久不变、永远指向最新版的固定地址，适合贴给别人或写进脚本；后者与版本绑定、永久有效，适合固定版本归档。页面上的版本号、发布日期、体积与更新说明都是**打开时现拉的**（自建源清单与 GitHub Release API 并行请求、互不依赖），所以发新版后不需要重新构建页面；两条源都不通时也不会给出死链 —— 自建源的固定键地址不依赖版本号，照样能下。
- **下载页顺带把安装这件事写全了**：三个平台各一个 Tab，含每个格式的安装命令（`chmod +x` 跑 AppImage、`sudo apt install ./xxx.deb`、`msiexec /i`、macOS 拖进「应用程序」），以及两个最常被问到的坑 —— Windows SmartScreen 的「未签名」提示、macOS 未公证的「无法验证开发者」，都给了可直接复制的处理命令；另外写清了数据目录（dsh 版本装在 `~/.dsh-launcher/versions/`，不污染全局 npm）。
- **下载页把能力清单也铺开了**：除了 8 条核心机制（插件为什么必须走官方命令、加速前缀为什么不写进 origin、配置为什么只重写目标小节…），页面还按「版本与安装 / 实例与终端 / 插件管理 / 配置与凭据 / 网络与更新 / 系统集成」六个领域，把 README 里的功能逐条列全 —— 不必翻文档就知道这个启动器到底管哪些事。页面**默认亮色主题**（右上角可切暗色，选择会记住），第一眼就是干净的纸底。
- **配置文件编辑器的高度不再写死**：那个代码高亮编辑器（全局配置、`cordis.patch.yml`、profile 的 `package.json` 共用）原来固定 **420px** —— 只改两行的配置也顶着一大片空白，而几百行的配置在宽屏上又白扔掉下半屏、还要多拖一条页面滚动条。现在高度自适应：**内容多高就多高**（最低留约 8 行），上限是「它在滚动容器里上方还剩多少高度」，长配置能填满窗口并只在编辑器内部滚动，页面不会被顶长、不会出现双滚动条；窗口缩放、上方说明块换行都会即时重算。编辑器在页面深处（如插件页一长串卡片之后的 `cordis.patch.yml`）或窗口很矮时会退回一个可用的固定高度，不会把长文件压成一条缝。
- **凭据可以写注释了，注释就写在键的上方**：以前 `refs` 里的每条凭据只有名字和值，一堆 `*_API_KEY` 到底哪个是干嘛的、哪个过期了，全靠记忆（只能自己在 YAML 里手写注释，而保存一次这些注释就被抹掉）。现在**文件里键正上方那一行 `# 注释` 就是这条凭据的注释**：启动器会把它读出来、在列表里新加的一列直接显示，鼠标点一下就能就地改（回车或失焦提交、Esc 取消），留空即删掉那一行；添加与编辑弹窗里也各有一个注释字段。保存改成**逐行改写 refs 块**，不再整篇重新序列化 —— `records`、`version`、未知顶层键以及它们自己的注释（records 段的小节说明、更上面的分组注释）全部逐字节保留，值里的 `#`、`:` 与多行内容（如证书）也能安全往返。
- **从本地克隆里装子包，先确认再装**：以前在「本地克隆仓库」卡片里点子包后面的 `link`，点下去就直接开装 —— 装进的是哪个 profile、装的是哪个子包、来源是哪份克隆，全都得靠悬停提示自己拼。现在会先弹一个确认框，把这几件事一次写清：目标 profile、来源仓库（目录名 + 分支 + 提交 + 是否有本地改动）、子包路径与版本、以及真正交给 `dsh plugin` 的安装规格（`link:…`）。风险也提前说：克隆里没有 `lib/` 构建产物的子包会当场警告「dsh 加载不了，装后校验会因没有可加载入口把它当场卸掉」，并指路先给这份克隆点「更新（git pull）」（会顺带 `pnpm install` + `build`）；没有声明 `dsh.bundle` 的子包（列表里的「非插件包」）`link` 按钮直接置灰，不再点了等于白装，缺 `lib/` 的候选也会在列表里先标出来。
- **每个 dsh 版本都能点开看「改了什么」**：以前想知道某个版本带来了什么，只能自己上 GitHub 翻 Release —— 版本表里只有版本号、日期、大小。现在版本表每一行都多了一个「更新日志」按钮，卡片工具栏也有一个，点开是一个版本浏览器：左栏列出全部版本（有 Release 的带绿点、早期没建 Release 的标「无发布说明」），右栏是该版本官方 Release 正文，标题与条目按原样排版；官方发的是中英双段，对话框里可以直接切「中文 / English」（默认中文），底部还有「查看这一版的完整提交对比」直达 GitHub 的 compare 页。正文一次拉全量并缓存（10 分钟 + ETag 条件请求，命中 304 不计额度），所以前后翻版本是零等待；匿名额度被限流时会提示去设置里填 GitHub Token。
- **侧栏底部重做：环境数据收成两张卡片，主栏底栏撤掉，并新增项目仓库入口**：底部数据以前散在两处 —— 侧栏是「三行灯 + registry + 数据目录」，主栏底下还压着一条状态栏写「官方源 / 数据目录 / 托盘提示」：同一批信息两处都不全，窗口一窄那条底栏还会被逐级藏掉。现在主栏底栏整个去掉，全部并进侧栏底部：「运行状态」卡片一行一灯（Node / 当前 dsh 版本 / 运行中实例数），「目录与源」把 registry、启动器数据目录、版本目录、dsh 数据目录各排一行、标签左对齐成一列；路径自动缩成 `~/.dsh-launcher/versions` 这种形式（完整值仍在悬停提示里），鼠标移到行尾可一键复制完整路径。卡片最下面新增「项目仓库」卡片：显示 `Yinxe/dsh-luncher`，提供「打开仓库」与「更新日志」两个按钮，反馈问题或查更新记录不用再去翻仓库地址；侧栏收起时这排退化成一排状态灯 + 一个仓库图标按钮。
- **版本列表在窄窗口下不再换行 / 横向溢出**：装过的版本每行右侧原来铺着「更新日志 / 打开安装目录 / 重装 / 卸载」这几个次要操作，窗口一窄就折成两行、三行（行高从 49px 涨到 113px，而且每行高度还参差不齐），再窄一点整张表连横向滚动条都拖出来了（表格写死了最小宽度 600px）。现在改成按**这张卡片实际有多宽**响应（容器查询，侧栏收放也算进去）：次要操作收进行尾的「更多」菜单，主操作（安装 / 设为当前）始终留在外面；「发布日期」「大小」两列按宽度逐级收起，窄到卡片只有 456px（窗口最小宽度 480px 时的实际内容宽度）仍保留「版本 / 状态 / 操作」三列。实测 456px → 1000px：**每一行都是单行 49px、零横向溢出**。顺带去掉一个重复徽标——被标记为 latest 的版本原来并排显示「LATEST」和「latest」两个同义徽标，现在只留一个。
