# DSH Starter v0.3.1 发布说明

发布日期：2026-09-23
GitHub Release：https://github.com/Yinxe/dsh-starter/releases/tag/v0.3.1

> 本文件由 `npm run notes:archive` 从 CHANGELOG.md 生成，请勿手改。

### 新增

- **首页全面美化，动作补齐**：web 实例卡更名「**DeepSeek Harness**」（前景色→主题色渐变标题 + dsh 黑鲸 logo + 鲸鱼水印/波浪背景装饰），除启动外新增**配置 / 打开界面 / 重启 / 停止**快捷按钮，与 Profiles 卡片同一套确认框与在途守卫。页面最后新增「**环境信息**」卡：系统/dsh/Node/npm 四个小格一卡看全（各带状态点），主题色渐变洗底 + 鲸鱼水印，悬停浮起、整卡可点直达「版本与安装」。DeepSeek 对话卡换成蓝色鲸鱼 + 渐变「Chat」字样并加了气泡背景；三张卡入场自上而下轻微错峰，鲸鱼水印悬停缓慢放大。**顶栏新增常驻「打开 DeepSeek Chat」按钮**，与首页入口同一动作（应用内独立窗口、可多开）。
- **Profiles 实例卡新增可点击复制的访问地址行**：Web 实例的运行地址不再挤在状态行里被截断，改为独占一行完整显示，点一下即复制到剪贴板（toast 确认，悬停提示完整地址）。
- **首页新增「DeepSeek 对话」入口**：一键在应用内独立窗口打开 DeepSeek 官方对话（chat.deepseek.com），与实例 Web UI 不同，这个入口**支持同时开多个窗口**——每次点击都会新开一个窗口，方便多个会话并排使用。
- **Profiles 双栏工作台：配置从「先选功能、再挑 profile」倒过来变成「先定 profile、再配一切」**：侧栏「插件管理」「模型配置」「配置文件」三个页面合并进「Profiles（实例与配置）」一页。左列还是实例列表（启动/停止/重启/复制/改名/删除全在），点任意一行的「配置」按钮，右列即打开该 profile 的配置工作台：**快捷配置**（Web 绑定/端口/来源，仅 Web profile）/ **模型** / **插件** / **配置文件**（`cordis.patch.yml`）/ **package.json** 五个 Tab，切来切去未保存的编辑不丢；窄窗口下工作台占满整页，「返回」回到列表。
- **0.1.7+ 模型配置按 profile 读写，并支持「同步到其他 profile…」**：dsh 从 0.1.7 起设置改为**每个 profile 独立**（存于该 profile 的 `cordis.patch.yml`）。绑定 ≥0.1.7 的 profile 在「模型」Tab 的保存只写它自己——`llm-pi-ai` / `agent-default-model` 两个条目由启动器整块接管，**其余条目、`!!js` 自定义行与节外注释逐字节不动**；旁边新增「同步到其他 profile…」，弹窗勾选其它 ≥0.1.7 的 profile 可批量写入同一份模型配置，旧版目标自动置灰跳过、失败逐个列明原因。若 patch 里出现两份同名条目（dsh 表单又改过一次），页面会警示「后者生效」。
- **旧版 dsh（<0.1.7）启动/编辑前自动还原全局配置**：0.1.7 迁移会把 `~/.dsh/settings.yaml` 改名成 `settings.yaml.imported`，旧版 dsh 不认识这个名字、启动后读不到任何配置。现在 `settings.yaml` 缺失时启动器会自动复制还原一份——**优先 `settings.starter-bak`（启动器上次覆写 settings.yaml 前留下的完整快照）**，没有才退回 `.imported`（其中只剩被导入拒绝的节，并非完整存档）；两个源文件都不改动。还原触发点不止「启动」：旧版 profile 读写模型配置、打开「配置文件」编辑全局 settings.yaml 时同样先尝试还原，杜绝在空配置上编辑后覆盖掉唯一存档。启动还原有 toast 明示还原到哪，还原来源记入诊断日志。
- **配置文件 Tab：迁移档案只读查看、旧全局与当前 patch 双文件切换**：0.1.7 迁移后被归档的旧全局配置可用「旧全局配置（imported）」弹窗**只读**查看（迁移时哪些节没被接受，去这里找）；绑定旧版的 profile 在本 Tab 仍可编辑全局 `settings.yaml`（可在两个文件间切换），并标注「将随 0.1.6 之前的版本支持一并弃用」。
- **通用终端面板（顶栏「终端」，右侧常驻栏）**：实例实时日志、插件安装/卸载/升级、dsh 版本安装、内置 Node 安装四类终端任务统一收进右侧同一个面板。上方任务列表按「实例 / 插件任务 / 系统任务」分组，每行状态点 + 耗时/进度；下方是选中任务的输出区：逐行按流着色（stderr 红色）、自动滚底（上滑后可一键跳回）、复制/导出到 `~/.dsh-starter/logs/`。宽屏点顶栏「终端」右栏滑入，与内容并排不遮挡；启动实例或开始任何安装时自动展开并聚焦该任务；小窗口（<1280px）自动切换为侧边抽屉（覆盖式，不挤占内容宽度）。插件任务运行中可就地取消、失败可重试、被构建脚本拦住的可「允许构建脚本并重试」；dsh 版本安装可在面板里取消；「清理」一次收走全部已结束任务。原先分散的四处输出界面由它取代：「实例终端」抽屉、插件页内置终端（现只留「N 个插件任务进行中… 在终端中查看」状态条）、版本页的安装日志卡（现只留进度 + 取消 + 跳转）与 Node 安装的滚动日志行（现只留进度条）。
- **配置工作台记住上次使用的 Tab**：点开任意 profile 的「配置」时，默认停在你上次离开的 Tab（快捷配置 / 模型 / 插件 / 配置文件 / package.json）——在 web 上切到「插件」后，再打开 web-try 的配置也直接是「插件」页；从没有切换记录时显示第一个 Tab。

### 变更

- **全局玻璃质感 + DeepSeek 蓝动态极光背景**：主背景不再是静止的纯色底——换成两团缓慢漂移的极光彩斑，**以 DeepSeek 品牌蓝领头**（亮色：蓝/天蓝/青，暗色同族加深紫罗兰压角），两层以不同周期相向流动、叠加处溶出第三种颜色，整窗底色「一直在变」但强度很低，不抢内容；原控制台点阵纹理换为细颗粒纸纹（亮色像纸、暗色像微噪点，两主题下都只在近看时显形）。左侧栏、自绘标题栏、顶栏与右侧终端面板统一换成半透明 + 背景模糊的同一套材质，极光从它们背后透出来并跟着流动，面板不再是四块“闷”实色。卡片、弹窗等承载内容的表面保持实色，阅读对比不受影响；系统开启「减弱动态效果」时极光自动静止。
- **命令面板瘦身**：删掉按 profile 动态生成的「启动 X / 停止 X / 重启 X」与「打开 X 工作台」条目（这些动作仍完整保留在首页与 Profiles 卡片上，且带确认框与在途守卫）；「打开 DSH 主界面」不再显示完整 URL。
- **启动方式与打开方式下沉到各 profile 卡片，可独立控制**：Profiles 左列每张卡片底部新增「启动方式」（子进程 / 独立进程）与「打开方式」（独立窗口 / 系统默认浏览器，仅 Web 类型显示）两枚小开关，各自独立生效——可以让 web 跑独立进程、其它 profile 保持子进程；从没动过开关的 profile 仍跟随全局默认。开关不再显示小字说明，鼠标悬浮即有完整解释。运行中的 profile 切换「启动方式」会弹出重启确认框：「保存并重启」立即生效并重启该实例，「取消」则配置不生效、保持原样；停止状态随意切换、不打扰。同时左列卡片布局修复了内容溢出（运行状态文本不再一字一行挤爆），并加了 `min-w-0` 约束。
- **profile「配置」入口更醒目 + 「终端」常驻头部**：卡片上的「配置」按钮从行尾图标改为紧跟名称的**图标+文字**按钮，与启动/停止等操作明显区分；Profiles 左列顶部与顶栏都有「终端」按钮，一键开合右侧通用终端面板（见「新增」），不用再从「运行状态」弹窗里找。

- **侧栏与命令面板随工作台收敛**：侧栏删去「插件管理」「模型配置」「配置文件」三项，「Profile 实例」更名「Profiles（实例与配置）」；命令面板删掉对应三条导航、新增「打开 {profile} 工作台」命令；各页文案里指向旧三页的说法全部改指工作台的对应 Tab。
- **自研插件适配提醒（待办）**：0.1.7 起插件设置只有声明 `.volatile()` 的字段支持热更新，其余需重启实例生效；本仓库随附的自研 `dshp-*` 插件（独立仓库）需要补声明，另行安排。
- **换版本启动 profile 的提示改为精简警告，并新增「复制 profile 试用启动」**：原来那页长篇风险说明（升级/降级徽标、逐条后果、建议）收敛成一句——「dsh 启动版本与上次不一致，可能因插件或配置不兼容导致启动失败」，并把出路直接做成三个按钮：**取消**、**复制 profile 试用启动**（打开复制框并预填 `<原名>-try`，复制成功后**直接启动这份副本**，跑不起来原实例也不受影响）、**同意风险，强制启动**（行为与原来「已知风险，继续启动」一致，成功启动后记为新的绑定版本）。
- **app 日志不再被「进程枚举 …ms ok=true」刷屏**：后台进程枚举是每几秒一次的常驻轮询，正常结果不再写 DEBUG 日志；只保留首轮一条 INFO 与异常/超时的 WARN，「系统日志」页里关键路径留痕不再被复读行顶出屏幕。

### 修复

- **小屏下「插件」Tab 的卡片撑破页面**：窄屏（工作台占满整页）时，插件包里超长的「插件 ID: …」列表会把整张卡片撑得比窗口还宽，内容直接溢出屏幕、右侧的卸载/开关按钮被顶出可视区，长文也没有省略号。现在窄屏下列表按容器宽度收缩，超长行正常截断为省略号（悬停仍可见全文）。
- **0.1.7 降回旧版后「还原」出的 settings.yaml 是残缺存档（丢配置实录）**：旧还原逻辑把 `settings.yaml.imported` 当成完整存档，可按官方迁移语义，导入成功的节已搬进首个 ≥0.1.7 profile 的 patch，`.imported` 里只剩被拒绝的节（实测 52 字节 vs 原文件 8.9KB）——降级后旧版读到的是近乎空的配置；且模型配置/配置文件页把「文件不存在」当「没有配置」，此时点保存会直接以空底稿覆盖出半份配置。三处同修：① 还原源改为优先 `settings.starter-bak`（启动器覆写前的完整快照），无则退回 `.imported`，日志标明来源；② 旧版配置的各读写入口（启动前、模型配置 Tab 读/存、「配置文件」全局 settings.yaml 读/存）在文件缺失时都先尝试还原，杜绝空配置覆盖；③ 删除 profile 时新增风险预检——`settings.yaml` 缺失且该 profile 补丁里带着从全局导入的节（即它可能握着唯一完整副本）时，确认框红字警示并给出「先恢复 settings.yaml 再删」的出路。
- **macOS 上最小化（或隐藏到托盘）后点 Dock 图标即可唤回主窗口**：以前窗口收起后再点应用图标没有任何反应，只能从菜单栏状态栏的「打开主界面」唤出 —— 系统递给应用的「重新打开」请求没有被处理。现在点 Dock 图标会把主窗口取消最小化、带回前台并聚焦。
- **降级后 dsh Web 界面打不开（空白/渲染失败）**：高版本 dsh 的界面会往浏览器本地存储写入低版本读不懂的数据，切回低版本后页面一启动就崩溃。现在以「独立窗口」方式打开实例 Web UI 时，会在页面自身脚本运行前自动清除 `dsh.*` 的本地存储项，低版本拿到的是干净数据。**注意**：这也会顺带清掉 dsh 界面自己存在这些键里的登录态/偏好，需要重新登录一次。「系统默认浏览器」方式打开不受影响（启动器无法触达外部浏览器的存储）。
- **独立窗口打开 dsh 界面不再白屏刺眼**：以前窗口先亮出来、页面还在加载，中间是一大块刺眼白屏。现在窗口按当前主题（深色/浅色）预铺底色，创建即显示，首帧就是与主题同色的画面。（此前的「隐藏创建、首屏加载完成后才显示」会触发 GTK 的窗口命中区缺陷——标题栏的最小化/最大化/关闭按钮点不动，非要一次缩放窗口才恢复；底色 + 加载遮罩已经把白屏挡住了，藏窗口没有必要，故改回创建即可见。）
- **独立窗口加载期改为「进度条等待页」，SPA 渲染前的白屏彻底消失**：上一修复解决的只是「窗口底色」，但 dsh 界面是单页应用——HTML 加载完成时窗口已亮出，可页面自身脚本（打包体积不小，且要整个跑完才算首帧就绪）还要执行好一会儿，这期间仍是白屏。现在加载遮罩在**页面任何脚本运行前**就注入并立即挂上，窗口亮出的第一帧就是与主题同色的等待页（滚动进度条 +「正在加载…」），检测到页面真正渲染出内容再淡出移除；超过 10 秒仍无内容也会强制移除，不会一直挡着。DeepSeek 等外部站点同样受益。
- **复制 profile 后副本一启动就报「cannot resolve profile bundle」**：复制会跳过 `node_modules`（可重建产物），但 dsh 并不会在首次启动时自动重装依赖，于是副本里声明的插件全部解析失败、进程直接退出。现在复制流程会在拷贝完成后自动执行官方 `dsh plugin --profile <副本名> install` 装好依赖（按钮显示「复制并安装依赖…」，视网络情况可能需要几十秒）；**装依赖失败则整个副本回滚删除**并给可操作提示（检查网络/镜像后重试），不再留下启动必炸的半成品。此前复制出来的旧副本若启动报此错，删除后重新复制即可。
