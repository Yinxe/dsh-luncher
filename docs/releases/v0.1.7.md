# DSH Starter v0.1.7 发布说明

### 修复

- **独立进程启动的实例，侧边「实例终端」不再空白**：以「独立进程（后台常驻）」启动时，进程表还没重算（Windows 上枚举一轮要 1 秒级、另有 8 秒缓存），启动器会把刚拉起的实例误判成「已退出的残留登记」清掉 —— 日志文件路径随之丢失，于是日志文件里明明有内容，实例终端却一直读不到，实例还会被降级标成「非内嵌」。现在登记比当前进程表更新时不再判定存活，等进程表重算过再确认；独立进程的实时日志、web 地址与「打开日志」按钮恢复正常。
- **从自建源下载的安装包恢复原始文件名**：为了「一个永久不变的下载地址」，R2 上的对象键被改成了 `windows-x64-setup.exe` 这类平台名，结果手动下载时文件名里没有版本号、也认不出是哪个包（自动更新不受影响 —— 它按文件头判断类型）。现在每个对象都带 `Content-Disposition`，下载保存名恢复为原始资产名（如 `DSH.Starter_0.1.6_x64-setup.exe`），直链依旧永久不变。
- **插件安装时能看出 clone 到底走没走 GitHub 加速**：加速是靠 git 的 `insteadOf` 在进程内部改写地址的，所以地址框和终端里显示的一直是原始 github 地址，很容易误判成「没加速」。现在安装页会直接写出**实际请求地址**（没加速时说明原因：本次关掉了 / 还没测速 / 没有支持 git 的前缀），任务日志里也会逐条列出。顺带点明一个真实边界：`git@github.com:owner/repo` 这类 SSH 地址不在改写范围内，要走加速得填 https 地址。
