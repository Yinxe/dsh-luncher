# DSH Launcher v0.1.3 发布说明

发布日期：2026-09-21
GitHub Release：https://github.com/Yinxe/dsh-luncher/releases/tag/v0.1.3

> 本文件由 `npm run notes:archive` 从 CHANGELOG.md 生成，请勿手改。

### 安全

- **伪 github 地址不再被代理**：只有真正的 github 域名才会走加速代理；像 `github.com.evil.test` 这类开头相同的相似主机不再被前缀匹配误判、悄悄丢给第三方代理（顺带修正了主机名大小写判定）。
- **外部输入统一转义 / 校验**：内置 Node 解压（PowerShell）、终端启动的 PATH 设置、GitHub ref / 包名等在落到
  shell 命令或 URL 之前会正确转义或校验。路径带引号（如用户名含 `'`）时不再把命令拼坏，也杜绝了借 URL 拼接
  访问到异常地址、把空参数拼丢导致命令行错位等问题。
- **git 克隆更防注入**：clone 安装 / 探测仓库时填的「分支 / 标签名」会先校验再拼给 git，以 `-` 开头的值
  （会被 git 当成命令行选项）直接拒绝；monorepo 子包路径里的 `..` 会被清洗，`link:` 目标始终落在克隆目录内，
  指不到仓库之外。
- **报错不再泄露凭据**：把带账号 / token 的私有 registry 地址写进错误提示或日志前会抹掉凭据（`https://user:tok@…`
  → `https://***@…`），避免 token 顺带显示在界面上。

### 修复

- **启动参数支持带空格的引号值**：在「默认启动参数 / 启动 args」里写 `--title "a b"` 这类含空格的参数时，此前会被按空格拆坏并把引号原样带进参数；现在按引号正确分组，`a b` 作为单个参数传给 dsh（单 / 双引号、转义空格都支持）。
- **停止 profile 不再可能误杀无关程序（Windows）**：靠端口反查实例归属时，若读不到目标进程的命令行（Windows 上此时只能凭映像名 `node.exe` 判断），此前会把任何恰好占着该端口的无关 Node 进程当成「本 profile 的实例」，停本 profile 时一并 taskkill 掉；现在拿不到命令行就拒绝归为本实例、只做「请手动处理」提示，界面仍会显示该端口为运行中。
- **独立进程启动登记失败不再谎报成功**：以「独立进程」方式启动时，若写入实例注册表失败（磁盘满、权限等），此前仍会提示「已启动」，但 macOS / Windows 上界面既看不到也停不掉这个实例；现在会立即终止刚拉起的 dsh 并如实报错。
- **实例列表轮询不再卡顿界面**：「运行中实例」每 3 秒刷新一次，此前这个枚举要在主线程里串行做进程存活校验、端口探测（每个连接最长等约 0.3 秒）、日志文件读取和 profile 扫描，端口多 / 有独立进程时整窗会短暂无响应；停止实例、停止 profile 同理。现在这几个操作都放到后台线程执行，界面不再被拖住。
- **关闭实例终端后不再后台空转读日志**：选中独立 / 外部进程实例、再收起「实例终端」抽屉后，此前仍每 1.5 秒 tail 一次它的日志文件、 indefinitely 在后台跑；现在只在抽屉打开时轮询。
- **安装内置 Node 时界面不再卡住**：下载完成后解压那几步（调用 tar / PowerShell 展开几十 MB 的归档，要跑好几秒）改到后台线程执行，解压期间窗口、托盘和其它点击不再短暂无响应。
- **添加凭据不再残留上一次输入**：打开「添加凭据」弹窗会先清空名称与值，避免上一次填的 token 悄悄留在表单里被再次带出。
- **插件终端「已省略 N 行」计数修正**：一次安装日志超出缓冲上限、旧行被裁掉时，此前提示一直显示 0；现在会如实累计被省略的行数。
- **软链接的 profile 不再被隐藏**：把 profile 目录 / 配置以符号链接放进 profiles 目录时，此前扫描既不当它是目录、也不当它是文件，直接从列表里消失（dsh 其实能透过软链运行）；现在解析软链目标后正常识别，指向不存在目标的坏软链仍安全跳过。
- **设置保存更抗损坏、token 权限收紧**：保存设置改为「先写临时文件、再原子替换」，写入过程中崩溃 / 断电不会再留下半截文件——此前损坏后下次启动会静默回到默认设置，把 GitHub token、镜像地址等一并覆盖掉；含 token 的设置文件权限收紧为仅本人可读写。
- **带构建号的版本号判定修正**：形如 `1.0.0+build.2` 的版本此前会被当成比 `1.0.0` 更新（误报有新版本、版本列表排错顺序）；现在按规范忽略 `+` 之后的构建元数据。
- **插件任务不再卡在进行中**：任务刚结束时刷新列表，更早的后端快照不会把已完成的任务退回「运行中」，避免转圈锁死、后续完成提示丢失；取消 / 清理遇到任务已消失也会自动与后端对齐。
- **版本「可升级」入口加在途守卫**：安装进行中时「可升级 →」链接一并禁用，不能连点重复触发安装。
- **配置文件不存在时可创建并保存**：dsh 全局配置在文件尚未生成时点「创建初始内容」，此前保存按钮仍置灰、无法落盘；现在创建后可正常保存。
- **自动更新不再误显示进度 / 卡死按钮**：deb / rpm 这类需要管理员授权的内置更新，后端本就不会静默自动安装，
  前端也不再自作主张把横幅顶成「下载安装中…」并禁用安装按钮——现在会正常显示「下载并安装（需管理员授权）」让你点。
- **更新安装中不再给「稍后」的假象**：一旦开始下载安装（成功后进程会自动重启、无法取消），横幅不再显示「稍后」，
  避免点了以为取消了、结果应用还是自己重启。
- **预发布版本渠道判定修正**：`-next` / `-canary` 等非 alpha/beta/rc 的预发布版本号不再被误标成「正式版」，
  归到预发布里，版本列表的筛选与标签都与实际一致。
- **右键托盘不再卡界面**：右键托盘刷新菜单同样改到后台线程执行（Windows 上枚举进程约需 1 秒），
  点了之后界面不会短暂失去响应。
- **打开配置详情不再卡界面**：查看某个 profile 的配置详情、切换插件包开关、创建「恢复模式」时，
  这些会调用 dsh / node 的重操作改到后台线程执行，主界面（窗口、托盘、其它点击）不再被短暂冻结。
- **配置保存不再误覆盖已有文件**：保存凭据、全局模型配置或插件开关时，若读取现有配置文件失败（权限 / 磁盘异常等，
  而非「文件不存在」），现在会直接报错并拒绝写入，不再把读取失败当成空文件、用新内容覆盖掉磁盘上已有的凭据 / 配置。
- **取消安装后不再卡住后续安装**：点「取消」杀掉带 `--foreground-scripts` 的安装时，后台收尾进程可能一直占着
  日志管道，导致安装任务久久不清、之后所有安装都被「已有安装任务正在进行」挡死；现在排空日志设了超时上限，
  取消后最多等几秒就放行。
- **设置页 GitHub 测速不再串结果**：打开设置读取缓存和手点「重新测速」并发时，较慢的旧请求不会覆盖较快新请求的结果，
  关闭抽屉后也不会再回写。
- **实例面板关闭后停止空转刷新**：右侧运行面板收起后不再每秒重渲染（运行时长只在打开时走动）。
- **本地克隆仓库删除防并发**：删除克隆仓库期间更新 / 删除 / link 按钮一并禁用并加在途守卫，避免旧的列表刷新把已删的行又填回来。
- **Windows 停止实例更安全**：结束进程 / 端口占用回退时，只有确认目标确为 node(dsh) 进程才动手，
  避免 PID 复用把无关程序误杀。
- **远端 refs 解析不再崩溃**：解析 git 引用列表时按字节处理，遇到含非 UTF-8 的引用名不再让整个查询崩溃。
- **插件页防串档**：快速切换 profile、或插件任务刷新间隙操作时，不再出现「把 A 的配置显示 / 保存进 B」的问题。
- **安装搜索防竞态**：连续搜索 / 连按回车不再让后返回的旧结果覆盖新结果（避免装成没搜过的包）；
  bundle 启用开关连点增加在途守卫。
- **切换 Node 来源失败会回滚**：保存失败时界面选项回退，不再与实际配置不一致。
- **scoped 包对账修复**：`@scope/包名@版本` 形式的插件不再被误解析成空包名，安装 / 卸载后的依赖对账恢复正常。
- **GitHub 加速不再干扰安装日志**：安装 / 流式任务的首行回显保持稳定，不受后台测速缓存影响。
- **启动器不再允许重复启动**：再次双击图标/快捷方式时，不再开出第二个主窗口、第二个托盘图标和两份后台轮询线程，
  而是把已有窗口唤回前台（隐藏到托盘的也会被唤出），新进程在创建窗口之前就退出；退出后单实例名正常释放。
- **连点「启动」不会起两个实例**：同一 profile 的启动请求在途时按钮转圈并禁用，避免后端唯一性守卫
  （依赖进程枚举，有扫描延迟）挡不住同一瞬间的两次请求。
